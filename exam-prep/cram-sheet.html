LOCKUNIX architecture / kernel–shell relationship — explain with a neat diagram
Part B · Q1(a) · 4–5 marks · appeared Apr 23 + Mar 24
Draw concentric circles: Hardware (centre) → Kernel → Shell → Applications/Users (outer).
Kernel: core of the OS, loaded at boot, stays in memory. Manages memory, processes, files, devices. Only the kernel talks to hardware. Programs reach it through system calls.
Shell: the command interpreter between user and kernel. Reads command → interprets → passes to kernel → returns output. Shell is a user program, so many can exist: Bourne (sh), C (csh), Korn (ksh), Bash.
Mention the shell interpretive cycle: prompt → read → parse → locate command in PATH → fork/exec → wait → prompt again.
LOCKFile permissions + chmod using absolute AND relative methods
Part B · Q2 · 3–4 marks · Part B 2 of 3 papers, Part A 3 of 3
9 bits = 3 sets (owner / group / others) × rwx. ls -l shows -rwxr-xr-x.
Absolute (octal): r=4, w=2, x=1 → add them. chmod 755 file → rwxr-xr-x. chmod 644 → rw-r--r--. chmod 744 → rwxr--r--.
Relative (symbolic): 3 components — who (u/g/o/a) + operator (+ − =) + permission (r/w/x). chmod u+x file, chmod go-w file, chmod a=r file.
Directory meaning: r = list it, w = create/delete files in it, x = cd into it. Default file perms 666 (rw-rw-rw-), directories 777, masked by umask.

LOCKProcess utilities — types of process, initialization & termination, nice / renice
Part B · Q3(b) · 4–5 marks · 3 of 3 papers, angle rotates — cover all three
Types: interactive/foreground, background (&), daemon (system background, e.g. init, cron), zombie (finished but parent hasn't collected status), orphan (parent died, adopted by init).
Init & termination: fork() creates a child (copy of parent), exec() overlays it with the new program, parent wait()s, child exit()s returning status. init is PID 1, ancestor of every process. Boot order: init → getty → login → shell.
Priority: nice value −20 (highest priority) to +19 (lowest), default 0. nice -n 10 command starts a command at lower priority. renice -n 5 -p PID changes a running process. Only root can raise priority (negative nice).
Related: ps (-f full, -e all, -u user), kill PID, kill -9, jobs.

HIGHEST CONFIDENCEExplain the three standard streams / standard redirection files of UNIX
Part B · Q5(a) · 3–5 marks · ALL 3 PAPERS, same slot
Every process opens three files by default:
stdin — fd 0 — standard input — default keyboard
stdout — fd 1 — standard output — default terminal/screen
stderr — fd 2 — standard error — default terminal/screen
Redirection: > output, overwrite · >> output, append · < input · 2> errors · 2>> append errors · > file 2>&1 both to one file · /dev/null discards.
Examples: ls -l > out.txt · wc -l < file · cmd 2> err.log · sort < in.txt > out.txt
Diagram: a box labelled command, arrow 0 going in, arrows 1 and 2 coming out.
LOCKThe tee command — demonstrate it in a pipeline, with a diagram
Part B · Q5(b) or Q6(a) · 4–5 marks · 2 of 3 papers + a Part A MCQ
tee reads standard input and writes it to standard output AND to one or more files at the same time — it's a T-junction in a pipe. Lets you save intermediate output without breaking the pipeline.
Syntax: tee [-a] file  (-a appends instead of overwriting)
ls -l | tee list.txt | wc -l — saves the listing and passes it on to wc.
Diagram: input arrow → tee box → two output arrows, one to screen, one to file.
HIGHTypes of variables / environment variables  ·  alias  ·  command substitution
Part B · Q5(b) or Q6(b) · 3–4 marks · one of these three fills the slot
Variables: local/shell — x=10, echo $x, exists only in the current shell. Environment — exported, inherited by child processes. No spaces around =.
Standard ones: PATH (search path for commands) HOME SHELL USER/LOGNAME PS1 (primary prompt) PS2 (continuation prompt) TERM MAIL.
set lists all · env lists environment · export x promotes local → environment · unset x removes · readonly x.
alias: a short name for a long command. alias ll='ls -l' · unalias ll · alias alone lists all. Put them in .profile/.bashrc to persist.
Command substitution: replaces a command with its output. Backquotes `date` or $(date). echo "Today is $(date)" · echo "You have $(ls | wc -l) files".
IF ASKEDJob control — job states diagram, bg / fg, signals

States: Running (foreground) ⇄ Running (background) ⇄ Stopped/Suspended → Terminated.
cmd & start in background · Ctrl+Z suspend the foreground job (sends SIGTSTP) · bg %1 resume a stopped job in background · fg %1 bring a background job to foreground · jobs list with job numbers · kill %1.
Signals: SIGINT (Ctrl+C, interrupt) · SIGTSTP (Ctrl+Z, suspend, catchable) · SIGSTOP (suspend, cannot be caught or ignored) · SIGCONT (resume) · SIGKILL (kill -9, cannot be caught).

LOCK · FIXED 5-MARK FORMULADescribe the five categories of operators used in regular expressions
Part B · Q7 or Q8 · 5 marks · appeared twice, 5 marks both times, same phrasing
1 · Atoms — what to match: . any one character · [abc] character class · [^abc] negated class · [a-z] range · a literal character · \ escapes a metacharacter.
2 · Quantifiers / repetition — how many: * zero or more of the preceding · + one or more · ? zero or one · {m,n} m to n times.
3 · Anchors / position — where: ^ start of line · $ end of line. ^$ matches an empty line.
4 · Alternation & grouping: | or · ( ) group.
5 · Character classes: [[:alpha:]] [[:digit:]] [[:upper:]] [[:lower:]] [[:space:]] [[:alnum:]].
Give one example per category — e.g. grep "^a.*z$" file.
LOCKWhat is grep? Explain the grep operation with a flow chart  ·  grep vs egrep vs fgrep
Part B · Q7 or Q8 · 3–5 marks · Part B 3 of 3, Part A 3 of 3
grep = Global Regular Expression Print. Scans input line by line, prints every line matching the pattern. Syntax: grep [options] pattern filename(s). Quote the pattern.
Flow chart: Start → open file → read next line → does it match the pattern? → YES: print the line → NO: skip → more lines left? → YES: loop back → NO: stop.
Options: -i ignore case · -v invert, show non-matching · -c count of matching lines only · -n prefix line numbers · -l filenames only · -w whole word · -x whole line · -e multiple patterns · -E extended regex.
grep = basic regex (BRE) · egrep = extended regex, + ? | ( ) work without backslashes, = grep -E · fgrep = fixed strings only, no regex at all, fastest, = grep -F.
LOCKExplain the tr command with its options  ·  uniq with its options
Part B · Q8 · 4–5 marks · tr 2 of 3 in the Q8(a) slot, uniq 1 of 3 + 2 Part A MCQs
tr — translate characters. Key exam point: it takes input only from standard input — no filename argument, so you must redirect or pipe.
tr 'a-z' 'A-Z' < file lowercase→uppercase · tr -d '0-9' < file delete digits · tr -s ' ' < file squeeze repeated characters into one · tr -c complement the set · echo "hello" | tr 'a-z' 'A-Z' → HELLO
uniq — needs SORTED input (it only compares adjacent lines). -u only non-repeated lines · -d only duplicated lines · -c prefix each line with its count · -i ignore case. Typical: sort file | uniq -d.

HIGHCommand line arguments, exit status, && and ||
Part B · Q9(b) · 3–4 marks · three syllabus lines, one answer
Positional parameters: $0 script name · $1…$9 the arguments · $# number of arguments · $* all arguments as one string · $@ all as separate words · $? exit status of the last command · $$ PID of the current shell.
Exit status: every command returns one. 0 = success, non-zero = failure. Read it with $? — immediately, it is overwritten by the next command. exit n ends a script with status n.
Logical operators: cmd1 && cmd2 runs cmd2 only if cmd1 succeeded. cmd1 || cmd2 runs cmd2 only if cmd1 failed.
grep "unix" file && echo "Found" || echo "Not found"
read: read name takes one line from the keyboard. read a b c splits on whitespace. echo -n "Enter name: " then read name makes it interactive.
HIGHwhile / for looping  ·  set and shift  ·  $0
Part B · Q10(b) · 3–4 marks · last three syllabus lines of the unit
set assigns positional parameters: set 10 20 30 → $1=10, $2=20, $3=30. set `date` → $1=day, $2=month…
shift moves every parameter one place left — $2→$1, $3→$2 — and $# drops by one. shift n shifts by n. Lets a script walk more than 9 arguments.
$0 holds the name the script was invoked by. Link one script under several names (ln script other) and branch on case $0 in … so one file behaves differently per name.
i=1
while [ $i -le 5 ]
do
    echo $i
    i=`expr $i + 1`
done
