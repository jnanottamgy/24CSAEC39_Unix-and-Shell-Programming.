1. Explain with a figure the kernel and shell relationship in UNIX / Illustrate the layered UNIX architecture with a neat diagram.
LOCKPart B · Q1(a) · 4–5 marks · Apr 2023 + Mar 2024

UNIX has a layered architecture. Each layer talks only to the layer directly beneath it, so the user is insulated from the hardware.

        +-------------------------------------------+
        |   USERS  /  APPLICATION PROGRAMS          |
        |   (vi, cc, who, ls, user programs)        |
        |   +-----------------------------------+   |
        |   |   SHELL   (sh, csh, ksh, bash)    |   |
        |   |   command interpreter             |   |
        |   |   +---------------------------+   |   |
        |   |   |        KERNEL             |   |   |
        |   |   |  process mgmt, memory     |   |   |
        |   |   |  mgmt, file system,       |   |   |
        |   |   |  device drivers           |   |   |
        |   |   |   +-------------------+   |   |   |
        |   |   |   |    HARDWARE       |   |   |   |
        |   |   |   |  CPU, memory, I/O |   |   |   |
        |   |   |   +-------------------+   |   |   |
        |   |   +---------------------------+   |   |
        |   +-----------------------------------+   |
        +-------------------------------------------+
Kernel
  • The core of the operating system. Loaded into memory at boot time and stays resident until shutdown.
  • Manages memory, processes, the file system and devices. Schedules the CPU among processes.
  • Only the kernel communicates directly with the hardware. No user program touches hardware itself.
  • Programs request kernel services through system calls (open, read, write, fork, exec). This is the kernel's only interface to the outside.
  • There is exactly one kernel on a machine.
Shell
  • The command interpreter — the interface between the user and the kernel. It is not part of the kernel; it is an ordinary user program.
  • Reads the command typed at the prompt, interprets it, and has the kernel execute it, then displays the result.
  • Because it is a user program, many shells can exist and each user can choose one: Bourne shell (sh), C shell (csh), Korn shell (ksh), Bash.
  • Also a programming language — commands can be collected into a shell script.
Shell interpretive cycle

The shell repeats this loop for every command: display prompt → read the command line → parse it (split into words, expand wildcards and variables) → locate the command in PATH → fork a child and exec the command → wait for it to finish → display the prompt again.

Marks tip: the diagram alone is worth about half. Draw it, label all four layers, then write two or three lines each on kernel and shell. Mention system calls and shell interpretive cycle by name.
2. What are file permissions? Explain the use of chmod to change file permissions using both the absolute and the relative methods.
LOCKPart B · Q2 · 3–4 marks · Part B 2 of 3 papers, Part A 3 of 3

Every UNIX file has nine permission bits, arranged as three sets of three. The sets are owner (user), group, others; within each set the bits are r (read), w (write), x (execute).

$ ls -l note.txt
-rwxr-xr--  1 jnan cse  120 Sep 17 10:20 note.txt
 |__||__||__|
  |   |   +--- others : r--  (read only)
  |   +------- group  : r-x  (read, execute)
  +----------- owner  : rwx  (read, write, execute)
PermissionFileDirectory
r (read)display its contentslist the names in it (ls)
w (write)modify its contentscreate or delete files inside it
x (execute)run it as a programcd into it
Method 1 — Absolute (octal) method

Each permission has a weight: r = 4, w = 2, x = 1. Add the weights for each of the three sets to get a three-digit octal number.

OctalPermissionsMeaning
chmod 755 frwx r-x r-xowner all; group and others read + execute
chmod 644 frw- r-- r--owner read+write; everyone else read only
chmod 744 frwx r-- r--owner all; group and others read only
chmod 777 frwx rwx rwxeveryone everything
chmod 600 frw- --- ---private to the owner

Absolute is "set exactly this" — it replaces all nine bits, whatever they were before.

Method 2 — Relative (symbolic) method

The expression has three components: who + operator + permission.

ComponentValues
Whou user/owner · g group · o others · a all three
Operator+ add · - remove · = set exactly
Permissionr · w · x
chmod u+x  script.sh     add execute for the owner
chmod go-w note.txt      remove write from group and others
chmod a=r  note.txt      everyone gets read only
chmod u+x,go-r file      two expressions, separated by a comma

Relative is "change only what I name" — bits not mentioned keep their old value.

Also worth a line: default permission for an ordinary file is 666 (rw-rw-rw-) and for a directory 777; the actual permission is these minus the umask value (typically 022, giving 644 and 755). Only the owner or root may change a file's permissions.

6. Illustrate the various stages of a UNIX session with a neat diagram.
HIGHEST CONFIDENCEPart B · Q3(a) · 4–5 marks · ALL 3 PAPERS, same slot, near-identical wording

A UNIX session is everything between logging in and logging out. It has three stages: Login → Work (the session proper) → Logout.

              +-------------------+
              |   Login prompt    | <-----------------+
              |   login:          |                   |
              +---------+---------+                   |
                        | username                    |
                        v                             |
              +-------------------+                   |
              |  Password prompt  |                   |
              |  (not echoed)     |                   |
              +---------+---------+                   |
                        |                             |
                        v                             |
                   /---------\                        |
                  /  Verify   \     INVALID           |
                 / /etc/passwd \ --------------------+
                 \ /etc/shadow /   "login incorrect"
                  \-----------/
                        | VALID
                        v
              +---------------------------+
              |  Kernel starts the SHELL  |
              |  reads /etc/profile then  |
              |  ~/.profile  /  .bashrc   |
              +---------+-----------------+
                        v
              +---------------------------+
              |   $ prompt  -  WORK PHASE | <----+
              |   shell interpretive cycle|      | next
              |   read -> parse -> fork   |      | command
              |   -> exec -> wait -> print|------+
              +---------+-----------------+
                        | exit  or  Ctrl+D
                        v
              +-------------------+
              |      LOGOUT       |
              | shell terminates, |
              | back to login     |
              +-------------------+
1 · Login stage
  • The getty process displays the login: prompt on the terminal.
  • The user enters a username, then a password — which is not echoed to the screen.
  • login verifies the pair against /etc/passwd (user details) and /etc/shadow (encrypted passwords). The entered password is encrypted and the result compared — the stored password is never decrypted.
  • If verification fails, the message login incorrect appears and control returns to the login prompt.
2 · Work phase (the session)
  • On success the kernel starts the user's login shell, named in the last field of that user's /etc/passwd entry.
  • The shell runs the system profile /etc/profile, then the user's own ~/.profile (or .bash_profile / .bashrc) — this is where PATH, prompts and aliases get set.
  • The user is placed in their home directory and the $ prompt appears.
  • The shell now repeats the shell interpretive cycle for every command: display prompt → read the line → parse and expand → locate the command → fork and exec → wait → display output → prompt again.
3 · Logout stage
  • The user types exit or presses Ctrl+D (end-of-file) at the prompt.
  • The login shell terminates, the session's processes are cleaned up, and getty redisplays the login prompt for the next user.
Marks tip: this is the single most repeated question on the paper. Draw the flow with the invalid-password loop back to the login prompt — that arrow is what separates a full-mark diagram from a half-mark one. Name /etc/passwd, .profile and Ctrl+D explicitly.
7. Discuss process utilities — the types of process, process initialization and termination, and how nice and renice adjust the priority of a running process.
LOCKPart B · Q3(b) · 4–5 marks · 3 of 3 papers, angle rotates — all three covered here

A process is a program in execution. Every process has a unique PID, a parent (PPID), an owner, and a priority.

Types of process
TypeDescription
Interactive / foregroundStarted from the terminal and holds it — the shell waits for it to finish before returning the prompt.
BackgroundStarted with &. Runs while the shell returns the prompt immediately: sort big.txt &
DaemonA system process that runs continuously in the background, not attached to any terminal — init, cron, lpd, inetd.
ZombieHas finished executing, but its parent has not yet collected its exit status, so its entry remains in the process table.
OrphanIts parent died first. It is adopted by init (PID 1), which becomes its new parent.
Process initialization (creation)
  • fork() — a process creates a near-exact copy of itself. The copy is the child; it gets a new PID, and fork returns 0 to the child and the child's PID to the parent.
  • exec() — the child then overlays its own memory image with the new program to be run. No new process is created by exec; the same PID now runs different code.
  • wait() — the parent suspends itself until the child finishes and picks up its exit status.
  • This is the fork-and-exec mechanism: it is how the shell runs every external command.
  • init is PID 1, started by the kernel at boot, and is the ancestor of every other process. Boot sequence: init → getty → login → shell.
Process termination

A process ends by calling exit(n), returning an exit status n to its parent (0 = success). It can also be ended from outside with kill PID (SIGTERM, polite) or kill -9 PID (SIGKILL, cannot be refused).

Priority — nice and renice
  • Every process carries a nice value from −20 to +19, default 0. A process is "nice" to others when it gives up CPU — so −20 = highest priority, +19 = lowest.
  • nice starts a new command at a changed priority:
    nice -n 10 sort big.txt — runs with priority lowered by 10.
  • renice changes the priority of an already running process, identified by PID:
    renice -n 5 -p 4312 — lowers the priority of process 4312.
  • Only the superuser (root) can raise priority (use a negative nice value). An ordinary user may only lower their own processes' priority.
  • View priorities with ps -l (NI column) or top.
Related process commands

ps show process attributes (-f full, -e every process, -u user) · kill terminate · jobs list jobs of this shell · & run in background · wait · sleep n.

9. Explain the three standard streams / standard redirection files with respect to UNIX. What is redirection?
HIGHEST CONFIDENCEPart B · Q5(a) · 3–5 marks · ALL 3 PAPERS, same slot

When any UNIX command runs, the kernel opens three files automatically for it. These are the standard streams, and each has a fixed file descriptor number.

                          +-----------------+
   stdin  (0) ----------->|                 |-----------> stdout (1)
   default: keyboard      |    COMMAND      |   default: terminal screen
                          |                 |
                          |                 |-----------> stderr (2)
                          +-----------------+   default: terminal screen
StreamfdDefault source/targetPurpose
Standard input (stdin)0KeyboardWhere the command reads its input from
Standard output (stdout)1Terminal / screenWhere normal results are written
Standard error (stderr)2Terminal / screenWhere error messages are written — kept separate so errors don't pollute redirected output
Redirection

Redirection is the shell's ability to detach a standard stream from its default file and attach it to a file of the user's choosing. The command itself is unchanged and unaware — it still just reads fd 0 and writes fd 1. The shell does the reconnection before the command starts.

OperatorMeaningExample
>Output redirection — creates or overwritesls -l > list.txt
>>Output redirection — appends to the filedate >> log.txt
<Input redirection — read from a file instead of the keyboardwc -l < list.txt
2>Redirect errors onlyls xyz 2> err.log
2>>Append errorscmd 2>> err.log
> f 2>&1Send both output and errors to the same filecmd > all.log 2>&1
/dev/nullThe "bit bucket" — anything written to it is discardedcmd 2> /dev/null
$ ls xyz               # xyz does not exist
ls: cannot access 'xyz': No such file or directory     <- goes to stderr (2)

$ ls xyz > out.txt     # only stdout redirected; the error STILL appears on screen
ls: cannot access 'xyz': No such file or directory

$ ls xyz 2> err.txt    # now the error goes to the file, screen stays clean
Marks tip: the example above — showing that > alone does not capture errors — is the cleanest way to demonstrate why stdout and stderr are separate streams. Examiners give credit for it.
10. Demonstrate the working of the tee command with a necessary diagram. Explain how tee can be integrated into a pipeline.
LOCKPart B · Q5(b) or Q6(a) · 4–5 marks · 2 of 3 papers + a Part A MCQ

tee reads from standard input and writes simultaneously to standard output and to one or more files. It is named after the plumbing T-junction: the data stream arrives and leaves in two directions at once.

                            +---------+
   stdin  ----------------->|   tee   |----------------> stdout (screen)
   (output of the           +----+----+                  passes on to the
    previous command)            |                       next command in
                                 v                       the pipeline
                            +---------+
                            |  file   |   (saved copy)
                            +---------+

Syntax: command | tee [-a] filename | next-command  — -a appends instead of overwriting.

Why it is needed

A pipe sends output onward only — once data flows into the next command it is gone, so you cannot see or save the intermediate result. Redirection with > does the opposite: it captures the output but ends the pipeline. tee solves both: it saves a copy and lets the data continue.

$ ls -l | tee list.txt | wc -l
12
                # list.txt now holds the full listing,
                # and wc -l still received it and printed the count

$ who | tee users.txt | grep "jnan"
                # saves everyone logged in, but displays only jnan's line

$ ls -l | tee -a log.txt | wc -l
                # appends to log.txt instead of overwriting it

$ cat file | tee copy1 copy2 copy3
                # tee can write to several files at once
Marks tip: draw the T-junction, give the three-stage pipeline example, and state the one-line reason: a pipe passes data on but does not save it; > saves data but stops the pipeline; tee does both.
11. Explain the types of variables in UNIX with examples. What are environment variables?
LIKELYPart B · Q5(b) or Q6(b) · 3–4 marks · Apr 2023 · two separate syllabus lines

A shell variable is a name holding a value. Assignment rule: no spaces around the = sign. Read a variable's value by prefixing $.

$ x=10          # correct
$ x = 10        # WRONG - shell reads x as a command
$ echo $x
10
TypeDescription

2. Environment variablesLocal variables that have been exported. They are passed to every child process the shell creates, so a script can read them. By convention written in UPPERCASE.
3. Shell / system variablesSet by the system at login, controlling how the shell behaves — PATH, HOME, PS1.
4. Positional parametersSet automatically from command-line arguments — $0 $1 $2 … $# $* $? (see Unit V).
Important environment variables

12. What is an alias? Explain creating and removing aliases. Explain the need for command substitution with an example.
LIKELYPart B · Q6(b) · 3–4 marks · Aug 2023 (alias) + Apr 2023 (command substitution)
Aliases

An alias is a short, user-defined name for a long or frequently used command, expanded by the shell before execution. It saves typing and lets you attach default options permanently.

$ alias ll='ls -l'            create an alias
$ alias rm='rm -i'            make deletion always ask first (a safety alias)
$ alias c=clear
$ alias                       list all defined aliases
$ alias ll                    show the definition of one alias
$ unalias ll                  remove an alias
$ \ls                         bypass an alias for one run (backslash)
  • No spaces around the =, and quote the command if it contains spaces or options.
  • Aliases defined at the prompt vanish when the shell exits — to make them permanent, put them in ~/.profile or ~/.bashrc.
Command substitution

Command substitution replaces a command with its own output, so the result of one command can be used inside another command or assigned to a variable.

Two forms: backquotes `command` (older) or $(command) (modern, and nestable).

$ echo "Today is date"           # WRONG - prints the word "date" literally
Today is date

$ echo "Today is `date`"         # command substitution
Today is Wed Sep 17 10:30:00 IST 2025

$ echo "You have $(ls | wc -l) files in this directory"
You have 12 files in this directory

$ today=$(date +%d-%m-%Y)        # store output in a variable
$ echo $today
17-09-2025

$ users=`who | wc -l`
$ echo "$users users are logged in"

Why it is needed: without it, a command's output can only go to the screen or a file. Command substitution lets that output become part of another command line — the shell runs the inner command first, drops its output in place, and only then runs the outer command. It is essential in shell scripts for storing computed results.

13. Illustrate the different job states in UNIX with a neat diagram. Demonstrate how bg and fg move a job between background and foreground. Examine the role of a signal such as SIGSTOP in job control.

Signals used in job control
SignalKeyEffect
SIGINT (2)Ctrl+CInterrupt — asks the process to terminate. Can be caught or ignored.
SIGTSTP (20)Ctrl+ZTerminal stop — suspends the job. Can be caught, so a program may refuse it.
SIGSTOP (19)—Stop the process. Cannot be caught, blocked or ignored — this is what guarantees job control always works, even against a program that traps Ctrl+Z.
SIGCONT (18)—Continue a stopped process — this is what bg and fg send.

$ sort bigfile.txt          # running in foreground

[1]+  Running    sort bigfile.txt &
$ fg %1                     # pull it back to the foreground
The SIGSTOP point that earns the mark: SIGTSTP (Ctrl+Z) can be caught and ignored by a program, but SIGSTOP cannot be — so the system always retains the ability to suspend any process.

The shell has no built-in comparison operators. test is a command that evaluates an expression and returns an exit status — 0 (true) if the expression holds, non-zero (false) otherwise. [ ] is simply another name for test.

19. Explain the case conditional with syntax and an example. Explain expr for computation and string handling.
UNIT VPart B · Q10(a) · 4–5 marks · the classic menu-driven-script question
The case conditional

case compares one value against several patterns and runs the matching block. It is cleaner than a long if-elif chain when you are testing the same variable repeatedly, and unlike if it does pattern matching, so wildcards work.

case $variable in
    pattern1)
        commands
        ;;
    pattern2 | pattern3)        # several patterns, separated by |
        commands
        ;;
    *)                          # default - matches anything
        commands
        ;;
esac
  • Each block must end with ;; — this is what stops execution falling through to the next pattern.
  • *) is the default case; put it last, as patterns are tried in order.
  • The whole construct is closed by esac (case spelled backwards).
  • Patterns may use shell wildcards: [Yy]*) matches yes, Yes, y, Y…
expr — computation and string handling

The shell treats everything as a string, so expr is the command that performs arithmetic. It evaluates an expression and prints the result.

Two rules that break scripts: every operand and operator must be separated by spaces (expr 5+3 prints "5+3"; expr 5 + 3 prints 8), and the multiplication sign must be escaped as \* because * is a shell wildcard.

$ expr 5 + 3          8         addition
$ expr 10 - 4         6         subtraction
$ expr 10 \* 2        20        multiplication - note the backslash
$ expr 10 / 3         3         integer division - remainder discarded
$ expr 10 % 3         1         modulus (remainder)

$ a=5 ; b=3
$ sum=`expr $a + $b`            store the result in a variable
$ echo $sum
8
$ sum=$(expr $a + $b)           the modern form does the same

String handling with expr:

ExpressionResultMeaning
expr length "hello"5Number of characters in the string
expr substr "hello" 2 3ellSubstring: 3 characters starting at position 2
expr index "hello" l3Position of the first occurrence of the character
Worked example — menu-driven calculator (case + expr + read)
#!/bin/sh
# Menu-driven calculator using case and expr

echo "1. Add"
echo "2. Subtract"
echo "3. Multiply"
echo "4. Divide"
echo -n "Enter your choice: "
read ch
echo -n "Enter two numbers: "
read a b

case $ch in
    1) echo "Sum = `expr $a + $b`"
       ;;
    2) echo "Difference = `expr $a - $b`"
       ;;
    3) echo "Product = `expr $a \* $b`"
       ;;
    4) if [ $b -eq 0 ]
       then
           echo "Error: division by zero"
       else
           echo "Quotient = `expr $a / $b`"
       fi
       ;;
    *) echo "Invalid choice"
       ;;
esac

exit and exit status
  • Every command returns an exit status to the shell when it finishes — a number from 0 to 255.
  • 0 means success. Any non-zero value means failure. (This is the reverse of C's convention for truth, and is a favourite MCQ.)
  • The status of the most recent command is held in $?. Read it immediately — the very next command overwrites it.
  • exit n terminates a script and returns status n to whoever called it. exit 0 conventionally signals success.
$ grep "unix" file.txt > /dev/null

0                     # 0 -> the pattern was found

$ grep "xyz" file.txt > /dev/null
$ echo $?
1                     # non-zero -> not found

21. Explain while looping and for looping with a list. Explain set and shift for manipulating positional parameters, and the use of $0 to call a script by different names.
UNIT VPart B · Q10(b) · 3–4 marks · the last syllabus lines of the unit
while — loop while a condition holds

Repeats the body as long as the condition is true (exit status 0). Closed by done. Use it when the number of repetitions is not known in advance.

i=1
while [ $i -le 5 ]
do
    echo "Number is $i"
    i=`expr $i + 1`          # the counter MUST be incremented,
done                         # or the loop never ends

Reading a file line by line is the other standard use:

while read line
do
    echo "Line: $line"
done < file.txt
for — loop over a list

Takes each item of a list in turn, assigns it to the variable, and runs the body once per item. Use it when the set of values is known.

for name in Amit John Ravi          # explicit list
do
    echo "Hello, $name"
done

for f in *.txt                      # wildcard expands to a file list
do
    echo "Processing $f"
    wc -l $f
done

for i in 1 2 3 4 5                  # a numeric list
do
    echo "Square of $i is `expr $i \* $i`"
done

for user in `who | cut -d' ' -f1`   # list from command substitution
do
    echo "Logged in: $user"
done

for arg in "$@"                     # loop over the script's arguments
do
    echo "Argument: $arg"
done
set — assigning positional parameters

set with arguments assigns them to the positional parameters $1, $2, $3…, overwriting whatever was there. This makes it a simple way to split a string into fields.

$ set 10 20 30
$ echo $1 $2 $3
10 20 30
$ echo $#
3

$ set `date`                  # split date's output into fields
$ echo $1                     Wed          (day)
$ echo $2                     Sep          (month)
$ echo $6                     2025         (year)
shift — moving the parameters left

shift discards $1 and moves every other parameter one place to the left: $2 becomes $1, $3 becomes $2, and $# decreases by one. shift n shifts by n places.

Why it exists: only $1 to $9 are directly accessible. shift lets a script walk through any number of arguments by repeatedly examining $1 and shifting.

$ set a b c d
$ echo $1 $2 $3 $4       ->  a b c d
$ shift
$ echo $1 $2 $3          ->  b c d        ("a" is gone, $# is now 3)
$ shift 2
$ echo $1                ->  d
#!/bin/sh
# Print every argument, however many there are
echo "Total arguments: $#"
while [ $# -gt 0 ]
do
    echo "Argument: $1"
    shift
done
$0 — calling a script by different names

$0 holds the name the script was actually invoked by, not the name it was written as. By creating links to one script under several names and branching on $0, a single script can behave differently depending on how it was called — which is how several real UNIX utilities are implemented.

$ ln greet hello            # create links to the same script
$ ln greet bye

$ cat greet
#!/bin/sh
case $0 in
    *hello) echo "Hello! Welcome." ;;
    *bye)   echo "Goodbye! See you." ;;
    *)      echo "Usage: call me as hello or bye" ;;
esac

$ ./hello        ->  Hello! Welcome.
$ ./bye          ->  Goodbye! See you.

The advantage is a single copy of the code with shared logic, instead of two nearly identical scripts to maintain.

(g) Check whether a file exists and report its permissions
#!/bin/sh
# File tests - -e -f -d -r -w -x

echo -n "Enter a filename: "
read fname

if [ ! -e $fname ]
then
    echo "$fname does not exist"
    exit 1
fi

if [ -d $fname ]
then
    echo "$fname is a directory"
elif [ -f $fname ]
then
    echo "$fname is a regular file"
fi

[ -r $fname ] && echo "Readable"
[ -w $fname ] && echo "Writable"
[ -x $fname ] && echo "Executable"

(h) Count the number of files in a directory using a for loop
#!/bin/sh
# for looping with a list

count=0
for f in *
do
    if [ -f $f ]
    then
        echo "File: $f"
        count=`expr $count + 1`
    fi
done

echo "Total regular files: $count"
Marking traps — check every script you write against these:
• Start with #!/bin/sh  • Use expr for arithmetic, never $(( ))  • Use [ ], never [[ ]]
• Spaces are required inside [ ] and around every expr operand  • No spaces around = when assigning
• Escape multiplication as \*  • Close with fi, done, esac  • End every case branch with ;;
• Increment the counter in a while loop, or it never terminates  • Add a sample run as a comment — lab records need the output transcript
